## FEATURE: A VS Code extension for Lugha — syntax highlighting, editing basics and `lughac check` diagnostics on open and save, in `editors/vscode/`.

**Status:** approved 2026-10-15 ("build it then merge to main") — built in session 140; proposed in session 139 as PRP-098 and renumbered to 099 because a concurrent session also took 098 (`prp-098-init.md`); the user chose to renumber this one.
**Milestone:** none (tooling, not a language milestone; no spec change, no tag).
**Spec:** §2 (lexical structure: keywords, comments, literals, interpolation, format specifiers, `char`), §5 (`format` templates), §9 (JSON diagnostics, exit codes 0/1/2), §11 (no default entry point).

**Decisions (discovery, session 139):**
- lives in this repo, `editors/vscode/`, so grammar changes ride with spec changes; split out later only if it needs its own releases;
- scope: highlighting + diagnostics; a language server (`lughac lsp`) is a later PRP;
- checks run on open and on save (`check` reads files from disk);
- the file checked: a file with `fun main` checks itself; a module file checks the `lugha.entries` setting's files; with none, the module is checked alone and E0303 is hidden;
- failures: one notification when `lughac` isn't found, an output channel and status-bar warning for exit 2, a newer check cancels an older one;
- always `--offline`: saving never runs `git`;
- tests: `node:test` for the logic (some against the real `lughac`), `vscode-tmgrammar-test` for the grammar; no VS Code integration tests;
- distribution: a local `.vsix` only, no Marketplace.
- No open entries in DECISIONS.md apply.

## OBJECTIVE
Open a `.la` file in VS Code and it is highlighted: keywords, types, strings with `{…}` interpolation, format specifiers, `char` literals, numbers, `//` comments. `//` toggles with Ctrl+/, brackets and quotes auto-close. Save it and `lughac check` runs; its errors and warnings appear as squiggles in the right files with their codes (E0403…) in the Problems panel, labels as related information and `help` in the message. Fix and save, and they go away.

```
cd editors/vscode && npm ci && npm test && npm run package
code --install-extension lugha-0.1.0.vsix
```

## CONTEXT
- **Starting state:** no editor support. `lughac check FILE --diagnostics=json [--offline]` prints one JSON object per diagnostic on stderr (`src/driver/json.rs`): `severity`, `code` (null for internal errors), `message`, `file`, `span` `{start,end}` each `{line, col, offset}` (null for internal errors), `label`, `labels[]` (`span`, `message`, optional `file`), `help`. Exit 0 (warnings only), 1 (program errors), 2 (bad usage / internal error).
- **Facts found in discovery** (checked with the real `lughac`):
  - `col` counts **bytes** from 1 (`driver/source.rs::line_col`); VS Code wants UTF-16 units, so the extension converts using the file's text and `offset`.
  - an error in an imported module names it **relative to the main file's folder** (`"file":"util.la"`); the main file itself is named as given on the command line;
  - std modules are named `<std>/math.la`; there is no file to put them on;
  - checking a module file alone gives E0303 "no `main` function" (and resolves its imports from its own folder);
  - there is no default entry point (§11 out of scope), so the main file can't be read from `lugha.toml`.
- **Ending state:**
  - New `editors/vscode/`:
    - `package.json` (language `lugha` for `*.la`, grammar, settings, scripts), `package-lock.json` (generated by npm), `tsconfig.json`, `.vscodeignore`, `README.md`;
    - `language-configuration.json`;
    - `syntaxes/lugha.tmLanguage.json`;
    - `src/extension.ts` — the only file importing `vscode`: activation, events, the diagnostic collection, output channel, status bar, notification;

### Design
1. **Settings** (`contributes.configuration`):
   - `lugha.path` (string, default `"lughac"`), **scope `machine`**, so a cloned repo's `.vscode/settings.json` can't point it at another program;
   - `lugha.entries` (string array, default `[]`), scope `resource`: workspace-relative `.la` paths of main files, e.g. `["src/main.la", "examples/demo.la"]`.
2. **What a check runs on** (`targets.ts`), for a `.la` file opened or saved in a workspace folder (a file with no folder checks itself):
   - `hasMain(text)`: a line matching `^\s*(public\s+)?fun\s+main\s*\(` outside a `//` comment → check the file itself;
   - else, with `lugha.entries` non-empty → check each entry. An entry must be relative, end in `.la`, and resolve (after `..`) inside the workspace folder; an invalid or missing one is reported once in the output channel and skipped;
   - else → check the file alone and drop E0303 from its results.
3. **Running** (`runner.ts`): `execFile(lugha.path, ["check", <abs path>, "--offline", "--diagnostics=json"], { cwd: <the file's folder>, timeout: 30 s })` — never a shell. One run at a time per target; a new request for the same target kills the old process and ignores its output. Result kinds:
   - exit 0 or 1 → the parsed diagnostics;
   - `ENOENT` → *not found*;
   - exit 2, any other exit, a signal or the timeout → *failed* with stderr.
4. **Diagnostics** (`diagnostics.ts`):
   - each stderr line is parsed as JSON; a line that isn't valid JSON or lacks `severity`/`message` is skipped and logged;
   - `file`: absolute as is; `<std>/…` → logged, not shown; else resolved against the **target's** folder;
   - range: from `offset`, converted to UTF-16 line/column using the file's current text on disk (a file that can't be read → the line from JSON, column 0);
   - `span: null` (internal error) → logged, and placed at line 1 of the target;
   - message: `message`, then `label` if any, then `help: …` on its own line; `code` as the diagnostic code; source `"lughac"`;
   - `labels` → related information (each in its own `file`, or the diagnostic's);
   - duplicates (the same file, range, code and message from two entries) shown once.
5. **Ownership:** each target owns the files its last run reported. A new result for a target first clears those files (unless another target also reports them), then sets the new ones. Closing a file doesn't clear it; deleting a file does.
6. **Failures** (`extension.ts`):
   - *not found* → one error notification per session, "lughac not found — set `lugha.path`", with a button opening the setting;
   - *failed* → stderr to the **Lugha** output channel, a status-bar item "$(warning) lughac failed" that opens the channel; earlier squiggles are kept. The next successful run hides the item.
7. **Grammar** (`source.lugha`):
   - `//` comments; keywords split into control (`if else while for in of match return break continue`), declaration (`fun extern struct enum impl interface let mut import private public`), constants (`true false self`), the operator `as`; the built-in types (`i8`…`u64 f32 f64 bool string char`) as `storage.type`;
   - `Self`, `Some None Ok Err Option Result` as built-ins; capitalized identifiers as types; the name after `fun` as a function name; a name before `(` as a call;
   - numbers: decimal with `_`, `0x…`, `0b…`, floats with exponent;
   - strings: escapes, `{{`/`}}`, `{…}` interpolation holding Lugha expressions (nested strings included) and an optional `:spec` before the closing `}`;
   - a string right after `format(` as a template: `{}` / `{:spec}` holes highlighted, nothing interpolated;
   - `char` literals with their escapes and `\u{…}`;
   - operators per §2.
8. **Language configuration:** line comment `//`; brackets `{}`, `[]`, `()`; auto-closing and surrounding pairs for those and `"`; `'` auto-closes outside strings; indent on `{`, outdent on `}`.
9. **Packaging:** `npm run package` → `vsce package --skip-license` → `lugha-0.1.0.vsix`. `package.json` `"license": "GPL-3.0-only"` (the human confirms the variant against `LICENSE`, which the model may not read). Zero runtime dependencies, so the `.vsix` holds only `out/`, the grammar, the configuration, `package.json` and `README.md`.

### Risk
- **Low.** Nothing in `lughac` changes. The extension only runs `lughac check --offline` on files the user opens, which lexes, parses and type-checks; nothing is compiled or executed.
- **Grammar drift:** a new keyword in a later milestone. Guarded by a test that reads §2's keyword block from the spec and requires every keyword in the grammar.

## ERROR HANDLING REQUIREMENTS
- `runner.ts` returns a tagged result, never throws for a process failure: `{ kind: "ok", diagnostics }`, `{ kind: "notFound" }`, `{ kind: "failed", exitCode | signal | timeout, stderr }`, `{ kind: "cancelled" }`.
- `diagnostics.ts` returns parsed records plus a list of skipped lines with reasons (not JSON, missing fields, `<std>` file); it never throws on bad input.
- `targets.ts` returns the targets plus rejected entries with reasons (absolute, not `.la`, outside the workspace, missing).
- Ignored on purpose: `cancelled` results (a newer run supersedes them).
- No uncaught exception may escape an event handler; each is caught and logged to the output channel.

## SECURITY CONSIDERATIONS
- **External input:** the workspace's files, `lugha.entries` and `lughac`'s output. Entries are validated (relative, `.la`, inside the workspace). Output lines are parsed as JSON, never evaluated.
- **The executable:** `lugha.path` is machine-scoped, so an opened (possibly untrusted) folder can't choose what runs. `lughac` is started with `execFile`, no shell, fixed arguments.
- **Network:** always `--offline`, so opening or saving never runs `git`, whatever the folder's `lugha.toml` says.
- No `unsafe`, crypto, credentials or secrets. Nothing sensitive is logged (only `lughac`'s own stderr and paths).
- **For the human's review:** the machine scope of `lugha.path` and always-offline checks are the two controls that make it safe to open an untrusted folder.
