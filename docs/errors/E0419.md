# E0419: Type argument doesn't satisfy its bound

A generic function or type was used with a type that misses one of its
bounds. `T: Ord` promises the body it may compare `T`s with `<`, `T: Eq`
that it may use `==`, and `T: Num` or `T: Float` that it may do arithmetic.
A type argument has to keep that promise, so a call with one that can't is
rejected where it is written, not deep inside the function.

```lugha
fun bigger<T: Ord>(a: T, b: T): T = if a > b { a } else { b };

fun main() {
    println(bigger([1, 2], [3])); // error: E0419
}
```

Arrays have no order, so `i64[]` isn't `Ord`. Other common cases: a `Ref`
(or a type holding one) as a `T: Eq`, `math.sqrt(2)` (an `i64` isn't
`Float`), and a method of an `impl Grid<T: Num>` block called on a
`Grid<string>`.

Pass a type that meets the bound, or compare something that has an order:

```lugha
fun bigger<T: Ord>(a: T, b: T): T = if a > b { a } else { b };

fun main() {
    println(bigger([1, 2].len, [3].len));
}
```

A struct of your own becomes `Ord` by giving it a `cmp` method:

```lugha
struct Size { n: i64 }

impl Size {
    fun cmp(self, other: Size): Ordering {
        if self.n < other.n {
            Ordering.Less
        } else if self.n > other.n {
            Ordering.Greater
        } else {
            Ordering.Equal
        }
    }
}

fun bigger<T: Ord>(a: T, b: T): T = if a > b { a } else { b };

fun main() {
    println(bigger(Size { n: 4 }, Size { n: 2 }).n);
}
```
