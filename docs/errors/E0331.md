# E0331: Linking failed with `[link]` input

The program's `[link]` tables (its own, or those of the packages it
uses) add libraries, folders or C files to the link, and the link
failed. Usually a library isn't installed or isn't where the linker
looks, or an `extern fun` names a C function none of the libraries
define. The help shows what the linker said. Without any `[link]` input
the link is lughac's own, and a failure there is an internal error
instead.

The example is a manifest and a program, so it isn't checked as one:

```text
# lugha.toml, on a system without raylib
[link]
libs = ["raylib"] # error: E0331

// main.la
extern fun InitWindow(width: i32, height: i32, title: string);
fun main() { InitWindow(800, 450, "hello"); }
```

Install the library (with its development files), or add the folder
that holds `libraylib.so` or `libraylib.a` to `paths`. If the linker
says a symbol is undefined, check the extern's name against the
library's header, and that the library providing it is in `libs`.
