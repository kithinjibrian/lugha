# E0321: A malformed `lugha.toml` (v8, v11; `name`/`source`, v15) or `lugha.lock`

A line of `lugha.toml` or `lugha.lock` isn't one lughac understands.
lughac reads only a small, strict subset of TOML, so a manifest means the
same thing to every reader, and anything outside it is reported at its
line instead of being guessed at. Common causes are an unquoted path, an
unknown table such as `[deps]`, a package listed twice, a git URL other
than `https://` or `file:///`, or `std` used as a package name (it is
reserved for the standard library).

These examples are manifests, so they aren't checked as programs:

```text
# lugha.toml
[packages]
geo = libs/geo # error: E0321
```

Quote the path:

```text
# lugha.toml
[packages]
geo = "libs/geo"
```

A git entry must use `https://` or `file:///`, carry no user name or
password, and give a `version`:

```text
# lugha.toml
[packages]
geo = { git = "ssh://example.com/geo" }          # error: E0321
geo = { git = "https://example.com/geo", version = "1.2" }
```

Credentials belong in git's own credential helper, never in a manifest.
`lugha.toml` holds only a `[packages]` table and a `[package]` table (with
`version`, `name` and `source`), each at most once. A malformed line in
`lugha.lock` is fixed by running `lughac update prog.la`, which writes the
lock again.
