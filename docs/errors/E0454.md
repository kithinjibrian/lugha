# E0454: A type with its own `eq` but not `hash`, or the other way round

A struct or enum may decide for itself what `==` means by writing
`fun eq(self, other: Self): bool`. Maps and sets find keys by their hash
first, so equal values must hash equal: a type that writes its own `eq`
writes its own `hash(self, h: u64): u64` too, from the same fields, and a
type that writes `hash` writes `eq`.

```lugha
struct User {
    id: i64,
    name: string,
}

impl User {
    fun eq(self, other: User): bool = self.id == other.id;
}

fun main() {
    let same = User { id: 1, name: "a" } == User { id: 1, name: "b" }; // error: E0454
}
```

Hash the fields `eq` compares:

```lugha
struct User {
    id: i64,
    name: string,
}

impl User {
    fun eq(self, other: User): bool = self.id == other.id;
    fun hash(self, h: u64): u64 = self.id.hash(h);
}

fun main() {
    println(User { id: 1, name: "a" } == User { id: 1, name: "b" });
}
```
