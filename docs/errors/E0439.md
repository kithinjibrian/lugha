# E0439: An actor used against its rules

An actor's state belongs to its own green thread. Outside the actor you
hold a handle: you start the actor with `spawn` and reach it only through
its methods, which are messages. So its fields can't be read or written
from outside:

```lugha
actor Counter {
    count: i64,
    fun get(self): i64 = self.count;
}

fun main() {
    let c = spawn Counter { count: 0 };
    println(c.count); // error: E0439
}
```

Ask the actor instead:

```lugha
actor Counter {
    count: i64,
    fun get(self): i64 = self.count;
}

fun main() {
    let c = spawn Counter { count: 0 };
    println(c.get());
}
```

The state exists only inside the actor, so a literal of it (or an
associated function returning it) may appear only right after `spawn`:

```lugha
actor Counter {
    count: i64,
}

fun main() {
    let state = Counter { count: 0 }; // error: E0439
}
```

Write `let c = spawn Counter { count: 0 };`.

Actors share nothing: what crosses an actor's boundary — its fields, its
methods' parameters and results — is copied, and may not hold a `Ref`. A
function value (whose closure may have captured one) or an interface value
(whose value may hold one) counts as holding one. Channels and other
actors' handles may cross, since they are messaging:

```lugha
actor Cache {
    hits: Ref<i64>, // error: E0439
}

fun main() {}
```

Keep the count in the actor itself:

```lugha
actor Cache {
    hits: i64,
    fun hit(mut self) { self.hits += 1; }
}

fun main() {
    let c = spawn Cache { hits: 0 };
    c.hit();
}
```

An actor can't have type parameters, nor can its methods, and it can't
declare a method named `stop`, `join` or `is`: every handle has those.
