# E0110: Source is not valid UTF-8

A source file has bytes that aren't valid UTF-8. Lugha reads every file as
UTF-8, and the error points at the first bad byte. It usually means the
file was saved in another encoding, such as Latin-1 or Windows-1252, by an
older editor.

An example can't be shown as text, since the bad byte isn't UTF-8. In a
Latin-1 file, `é` is the single byte `0xE9`:

```text
fun main() {
    println("caf<0xE9>");   // error: E0110 at the byte 0xE9
}
```

Save the file as UTF-8 (most editors have an encoding choice when saving),
or convert it, for example with `iconv -f latin1 -t utf-8 main.la`. The
`é` then becomes the two bytes UTF-8 uses, and the program checks.
