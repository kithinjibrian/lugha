# E0409: Type not allowed in an extern signature

An `extern fun` declares a C function, and its parameters and return
type must be things C understands: numbers, `bool`, `char`, `string` as
a parameter (passed as a C string), handles declared with `extern type`
and `Option` of a handle (v16), and function types as callback
parameters (v16). Arrays, structs, enums, other `Option`s and interface
values have Lugha's own layout, which C code can't read, and a C string
can't be returned as a Lugha `string` because it has no length header.
A callback's own parameters and result are narrower still: numbers,
`bool`, handles and `Option` of a handle, and no extern returns a
function.

```lugha
extern fun getenv(key: string): string; // error: E0409

fun main() {
    println("hi");
}
```

Return a number instead, and keep the string work on the Lugha side. For
environment variables, the standard library already has `std.env`:

```lugha
extern fun strlen(s: string): u64;

fun main() {
    println(strlen("hello"));
}
```

An array can't be passed either; pass its elements, or do the work in
Lugha:

```lugha
extern fun total(xs: i64[]): i64; // error: E0409

fun main() {
    println(1);
}
```

```lugha
fun total(xs: i64[]): i64 {
    let mut sum = 0;
    for x of xs {
        sum += x;
    }
    sum
}

fun main() {
    println(total([1, 2, 3]));
}
```

A callback can't take a string, since C's text has no length header:

```lugha
extern fun on_line(cb: fun(string)); // error: E0409

fun main() {}
```

Give the callback a handle or a number instead, and read the text through
another extern, or keep the text on the Lugha side.
