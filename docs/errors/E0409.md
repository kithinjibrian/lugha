# E0409: Type not allowed in an extern signature

An `extern fun` declares a C function, and its parameters and return
type must be things C understands: numbers, `bool`, `char`, `string`
(passed as a C string, and since v16 returned as a copy of C's text, with
`Option<string>` for C's `NULL`), handles declared with `extern type`
and `Option` of a handle (v16), and function types as callback
parameters (v16), and `extern struct`s by value (v16). Arrays, plain structs, enums, other `Option`s and interface
values have Lugha's own layout, which C code can't read.
A callback's own parameters and result are narrower still: numbers,
`bool`, handles and `Option` of a handle, and no extern returns a
function.

```lugha
extern fun struct_of(key: string): i64[]; // error: E0409

fun main() {
    println("hi");
}
```

Return a number instead, and keep the array work on the Lugha side. Text
is fine both ways since v16: C's text comes back as a copy, and
`Option<string>` turns C's `NULL` into `None`:

```lugha
extern fun getenv(name: string): Option<string>;

fun main() {
    println(getenv("HOME"));
}
```

An array goes to C as a pointer to its elements (v17) when C can read
them: numbers, `bool`, handles and extern structs. An array of strings
can't; pass each string, or do the work in Lugha:

```lugha
extern fun total(xs: string[]): i64; // error: E0409

fun main() {
    println(1);
}
```

```lugha
fun total(xs: string[]): i64 {
    let mut sum = 0;
    for x of xs {
        sum += x.len;
    }
    sum
}

fun main() {
    println(total(["a", "bc"]));
}
```

A callback may take C's text (`fun(string)`), copied, but can't give a
string back: C would keep a pointer into Lugha's memory, which the
collector may free:

```lugha
extern fun on_name(cb: fun(i64): string); // error: E0409

fun main() {}
```

Give C a handle or a number instead, or keep the text on the Lugha side.
