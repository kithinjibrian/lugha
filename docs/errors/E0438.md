# E0438: A `spawn` that changes a copy, or a malformed `select`

A green thread gets copies of what its call uses, as a closure does. A
call that changes its receiver — `push`, `pop` or `clear` on an array,
a `mut self` method, `swap` — would change the new thread's own copy,
which nobody else ever sees:

```lugha
fun main() {
    let mut xs = [1, 2];
    spawn xs.push(3); // error: E0438
    println(xs);
}
```

Send the result back through a channel, or share the value in a `Ref`:

```lugha
fun main() {
    let xs = Ref.new([1, 2]);
    let t = spawn fun() {
        xs.update(fun(v: i64[]): i64[] {
            let mut w = v;
            w.push(3);
            w
        });
    }();
    t.join();
    println(xs.get());
}
```

A `select` waits on channels, so it needs at least one `recv` or `send`
arm. It may have one `after(ms)` arm, which runs when nothing happened in
time, or one `default` arm, which runs at once when nothing is ready, but
not both: with `default` the `select` never waits, so the timeout could
never fire.

```lugha
fun main() {
    let c: Chan<i64> = Chan.new();
    select {
        m = c.recv() => println(m),
        after(10) => println("late"),
        default => println("nothing yet"), // error: E0438
    }
}
```

Keep the one you mean:

```lugha
fun main() {
    let c: Chan<i64> = Chan.new();
    select {
        m = c.recv() => println(m),
        default => println("nothing yet"),
    }
}
```

The value of a `recv` or `send` arm must be a `Chan`: a type with its own
`recv` method doesn't make a `select` arm.
