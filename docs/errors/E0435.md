# E0435: A malformed callback declaration

An extern can take a callback, a parameter with a function type such as
`cb: fun(i64)`, which C may call. When C hands the callback a `void *`
of user data, Lugha needs to know where: one of the callback's
parameters is written `data`, and so is one of the extern's own
parameters, where C takes that user data. A parameter written `release`
is the function C calls when it no longer needs the callback. lughac
fills in both arguments itself, so the shapes have to match: an extern
has a `data` parameter exactly when one of its callbacks takes `data`,
at most one of each, and `release` only together with `data`. Outside
an extern's signature, `data` and `release` mean nothing.

```lugha
extern fun on_tick(cb: fun(i64), user: data); // error: E0435

fun main() {}
```

Here nothing takes `user` back. Write `data` among the callback's
parameters, where the C function pointer receives it:

```lugha
extern fun on_tick(cb: fun(i64, data), user: data);

fun main() {
    let ticks = Ref.new(0);
    on_tick(fun(n: i64) { ticks.update(fun(t) = t + n); });
}
```

The call writes no argument for `user`: lughac passes the closure there.
If the C function has no user data at all, leave `data` out of both
places; such a callback takes only functions that capture nothing
(E0436).
