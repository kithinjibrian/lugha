# E0324: A package version that doesn't meet a requirement, or a requirement on a package without a version

A manifest asks for a version of a package, and the package's own
`lugha.toml` declares a version outside that range, or no version at all.
A requirement like `"1.2"` accepts the compatible versions, from 1.2.0 up
to but not including 2.0.0, so a program states which releases it works
with and learns at build time when a package changes beneath it.

The example needs two manifests, so it isn't checked as one program:

```text
# lugha.toml (the program)
[packages]
geo = { path = "libs/geo", version = "1.2" } # error: E0324

# libs/geo/lugha.toml
[package]
version = "2.0.0"
```

Either update the program for the new version and raise the requirement
(`version = "2"`), or use a release of the package that the requirement
accepts. If the package declares no version, add one to its `[package]`
table (`version = "1.2.0"`), or drop `version` from the entry. A git
package's version is its tag's, so this check doesn't apply to it.
