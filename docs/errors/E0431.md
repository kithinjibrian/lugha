# E0431: A bad format specifier

A hole in a string can carry a format specifier after a `:`, as in
`"{x:.2}"` or `"{n:05}"`. Each part of a specifier only makes sense for
some types: a precision (`.2`) for floats, hex and binary (`x`, `b`) for
integers, zero padding for numbers. A specifier that doesn't fit the value,
or isn't a specifier at all, is reported instead of being silently ignored.

```lugha
fun main() {
    let n = 7;
    println("{n:.2}"); // error: E0431
}
```

Other examples: `"{x:q}"` (no such kind), `"{f:x}"` with a float,
`"{s:05}"` with a string, and a width over the limit like `"{n:2000}"`.

Use a specifier that fits the type, or convert the value first:

```lugha
fun main() {
    let n = 7;
    println("{n:03}");
    let x = n as f64;
    println("{x:.2}");
}
```
