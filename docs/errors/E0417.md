# E0417: Non-exhaustive `match`

A `match` doesn't cover every value its subject can have. Lugha requires
every `match` to handle all cases, so a value can never fall through
with no arm to take it; when an enum gains a variant, every `match` that
forgot it is pointed out. The message names a value no arm covers.

```lugha
enum Shape { Circle(f64), Square(f64) }

fun area(s: Shape): f64 = match s { // error: E0417
    Circle(r) => 3.14 * r * r,
};

fun main() {
    println(area(Shape.Circle(1.0)));
}
```

Add an arm for each missing case:

```lugha
enum Shape { Circle(f64), Square(f64) }

fun area(s: Shape): f64 = match s {
    Circle(r) => 3.14 * r * r,
    Square(w) => w * w,
};

fun main() {
    println(area(Shape.Circle(1.0)));
}
```

Numbers and strings have too many values to list, so a `match` on one
needs a `_` arm:

```lugha
fun name(n: i64): string = match n { // error: E0417
    0 => "zero",
    1 => "one",
};

fun main() {
    println(name(1));
}
```

```lugha
fun name(n: i64): string = match n {
    0 => "zero",
    1 => "one",
    _ => "many",
};

fun main() {
    println(name(1));
}
```
