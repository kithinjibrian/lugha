# E0314: Import clash

Two imports in one file bind the same name, or an import binds a name that
an item of the file already has. `import a.util;` binds `util`, and
`import std.math { abs };` binds `abs`; each name may be bound once, so
`util.f()` or `abs(x)` always means one thing.

```lugha
import std.math;

struct math { x: i64 } // error: E0314

fun main() {}
```

Rename your item, or import the module under another name with `as`:

```lugha
import std.math as m;

struct math { x: i64 }

fun main() {
    println(m.max(1, 2));
}
```

Importing one name twice is the same clash:

```lugha
import std.math { abs, abs }; // error: E0314

fun main() {
    println(abs(-1));
}
```

```lugha
import std.math { abs };

fun main() {
    println(abs(-1));
}
```

Two modules whose paths end in the same name, like `import a.util;` and
`import b.util;`, clash too; give one of them an alias:
`import b.util as butil;`.

A module is imported once per file, aliases included, so a whole-module
import and a named one of the same module clash:

```lugha
import std.math;
import std.math { abs }; // error: E0314

fun main() {}
```

One import does both: `import std.math { abs };` binds `abs` and `math`.

```lugha
import std.math { abs };

fun main() {
    println(abs(-1) + math.max(1, 2));
}
```

The same holds for re-exports: a module offers another's items either as a
member (`public import raw;`, reached as `m.raw.X`) or by name
(`public import raw { X };` or `public import raw { * };`, reached as
`m.X`), not both in one file.

A glob re-export (`public import raw { * };`, v17) clashes the same way
when it brings a name the module already has, its own or another
import's, unless both are the same item; the message names both sources.
List the items you want instead of `*`.
