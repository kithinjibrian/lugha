# E0404: Operator applied to invalid operand types

An operator was used on values it isn't defined for: arithmetic on a
`bool`, `-` on an unsigned integer, `<` on a struct without a `cmp`
method, `==` on a type parameter without an `Eq` bound, and so on. Each
operator works on a fixed set of types, or on types that declare it with
a method such as `add` or `cmp`; anything else is caught here rather
than guessed at.

```lugha
fun main() {
    let done = true;
    let n = done + 1; // error: E0404
    println(n);
}
```

Turn the value into a number first:

```lugha
fun main() {
    let done = true;
    let n = if done { 1 } else { 0 } + 1;
    println(n);
}
```

In generic code, an operator needs a bound saying the type supports it:

```lugha
fun same<T>(a: T, b: T): bool = a == b; // error: E0404

fun main() {
    println(same(1, 2));
}
```

Add the bound:

```lugha
fun same<T: Eq>(a: T, b: T): bool = a == b;

fun main() {
    println(same(1, 2));
}
```
