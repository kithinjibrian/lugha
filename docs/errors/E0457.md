# E0457: An operand that fits more than one arithmetic method

A type may have several `add`, `sub`, `mul`, `div` or `rem` methods, one per
right-hand type, and the right operand picks one by its exact type. A plain
integer like `2` could be an `i64` or a `u8`, so when both exist it fits
both, and nothing decides between them:

```lugha
struct V { x: f64 }

impl V {
    fun mul(self, n: i64): V = V { x: self.x * (n as f64) };
    fun mul(self, n: u8): V = V { x: self.x * (n as f64) };
}

fun main() {
    let v = V { x: 1.0 };
    let w = v * 2; // error: E0457
}
```

Write the operand so it has one type:

```lugha
struct V { x: f64 }

impl V {
    fun mul(self, n: i64): V = V { x: self.x * (n as f64) };
    fun mul(self, n: u8): V = V { x: self.x * (n as f64) };
}

fun main() {
    let v = V { x: 1.0 };
    let w = v * (2 as i64);
    let u = v * (2 as u8);
}
```

The same happens when a generic type's methods take different type
parameters that turn out to be the same type, such as
`fun mul(self, a: A)` and `fun mul(self, b: B)` on a `P<f64, f64>`: give
one of them another name.
