# E0458: Arithmetic for a type you don't declare, in the wrong place

`impl f64 { … }` or `impl shapes.W { … }` adds arithmetic with that type on
the left: `fun mul(self, v: V): V` makes `2.0 * v` work. Such an `impl` can
only hold `add`, `sub`, `mul`, `div` and `rem` of the operator's shape, and
only in the module that declares the right-hand type. Otherwise two
packages could each define `f64 * V` differently, and a program importing
both would have two answers for one expression.

```lugha
struct V { x: f64 }

impl f64 {
    fun scale(self, v: V): V = V { x: self * v.x }; // error: E0458
}

fun main() {}
```

Write it as an operator method, beside the type it takes:

```lugha
struct V { x: f64 }

impl f64 {
    fun mul(self, v: V): V = V { x: self * v.x };
}

fun main() {
    let v = 2.0 * V { x: 1.0 };
}
```

An `impl f64` whose methods take no type of this module (`fun add(self,
k: i64): f64`) is E0458 too: `f64 + i64` belongs to neither of your types.
