# E0326: A git package that doesn't match `lugha.lock`

`lugha.lock` pins each git package to an exact commit, so every build of
the program uses the same code. When a locked package had to be cloned
again, its tag pointed at a different commit than the lock records. That
means the tag was moved after the program was locked, which could be an
honest re-release or a sign of tampering, so lughac stops instead of
building with code nobody has reviewed.

The example is a lock file and a repository, so it isn't checked as one
program:

```text
# lugha.lock
[locked]
geo = { git = "https://example.com/geo", version = "1.2", commit = "3f1c…" } # error: E0326

# the repository's tag v1.2.0 now points at commit 9ab0…
```

Find out why the tag moved. If the new commit is one you trust, run
`lughac update prog.la`, which re-resolves every git package and rewrites
`lugha.lock`; then review and commit the new lock.
