# E0318: A declaration exposing a less visible type

A declaration is more visible than a type in its signature. If `make`
returns a `private` struct `S`, other modules could call `make` but not
name, build or understand what they get back. So a function, field, method
or re-export may only mention types at least as visible as itself: a
package-level function may use package-level and `public` types, and a
`public` function only `public` ones.

```lugha
private struct Secret { n: i64 }

fun make(): Secret = Secret { n: 1 }; // error: E0318

fun main() {
    println(make().n);
}
```

Either make the type as visible as the function, or the function as hidden
as the type:

```lugha
private struct Secret { n: i64 }

private fun make(): Secret = Secret { n: 1 };

fun main() {
    println(make().n);
}
```

The same holds for `public`: a `public fun a(): Inner` needs `Inner` to be
`public`, and `public import util { helper };` needs `helper` to be
`public`.
