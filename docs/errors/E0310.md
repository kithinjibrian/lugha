# E0310: Method declared twice, or named like a member it can't be told from

Two members of a type may share a name only when every use shows which
one is meant. A field and a method can: `p.name` is the field and
`p.name()` the method. A variant and a method with `self` can too:
`Shape.Circle(1.0)` is the variant and `s.Circle()` the method. Where the
same text would mean either, the method is E0310:

- a method named like a field that holds a function: `q.area(5)` could
  call the field or the method;
- an associated function (no `self`) named like a variant:
  `Shape.Circle(1.0)` could build the variant or call the function;
- two methods with one name, even in separate `impl` blocks.

```lugha
struct Q { area: fun(i64): i64 }

impl Q {
    fun area(self, x: i64): i64 = x + 1000; // error: E0310
}

fun main() {}
```

Give the method a name of its own, or call the field through a method
that says what it does:

```lugha
struct Q { area: fun(i64): i64 }

impl Q {
    fun scaled_area(self, x: i64): i64 = self.area(x) + 1000;
}

fun main() {
    let q = Q { area: fun(x) = x * 2 };
    println(q.area(5));
    println(q.scaled_area(5));
}
```

An associated function named like a variant:

```lugha
enum Shape { Circle(f64) }

impl Shape {
    fun Circle(r: f64): Shape = Shape.Circle(r * 2.0); // error: E0310
}

fun main() {}
```

```lugha
enum Shape { Circle(f64) }

impl Shape {
    fun doubled(r: f64): Shape = Shape.Circle(r * 2.0);
}

fun main() {
    println(Shape.doubled(1.0));
}
```

Two methods with one name:

```lugha
struct Counter { n: i64 }

impl Counter {
    fun get(self): i64 = self.n;
}

impl Counter {
    fun get(self): i64 = self.n * 2; // error: E0310
}

fun main() {}
```

```lugha
struct Counter { n: i64 }

impl Counter {
    fun get(self): i64 = self.n;
    fun doubled(self): i64 = self.n * 2;
}

fun main() {
    let c = Counter { n: 3 };
    println(c.get());
    println(c.doubled());
}
```

Before v17 (milestone 123), any method named like a field or a variant was
E0310.
