# E0449: An extern struct crosses to C by value on a target without C's struct rules

On x86-64 lughac passes an `extern struct` to and from C by value exactly
as a C compiler would. On `aarch64-unknown-linux-gnu` (v17, milestone 133)
it doesn't know ARM's rules for that yet, so rather than build code C would
misread, every place an extern struct crosses by value is refused: an
extern's parameter or result, or a callback's.

```text
error[E0449]: an extern struct can't cross to C by value on aarch64 yet
 --> main.la:2:19
  |
2 | extern fun area(r: Rect): f64;
  |                    ^^^^
```

Passing it by pointer works on every target. If you write the C side too,
take a pointer there (`double area(const Rect *r)`) and write `ptr` here:

```lugha
extern struct Rect { w: f64, h: f64 }
extern fun area(ptr r: Rect): f64;

fun main() {
    let r = Rect { w: 2.0, h: 3.0 };
    println(area(ptr r));
}
```

Or build for x86-64, the default target, where by value is supported.
`lughac check` doesn't report E0449: it is checked by `lughac build
--target aarch64-unknown-linux-gnu`.
